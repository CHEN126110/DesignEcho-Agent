# 电商主图设计结构化框架（用户方法论）

> 来源：用户 2026-06-12 提供的主图设计理解，作为主图相关角色提示、知识工具与评审标准的权威业务依据。
> 运行时消费方式：`shared/knowledge/main-image-framework.ts` 知识模块 + `getMainImageDesignFramework` 知识工具（模型按需检索，不硬编码进 Agent）。

## 0. 总定义

主图 = 点击图 + 转化图

| 类型 | 核心问题 | 目标 |
| --- | --- | --- |
| 点击图 | 用户为什么点？ | 提高点击率 |
| 转化图 | 用户为什么买？ | 提高转化率 |

点击图负责吸引，转化图负责说服。点击图解决"为什么点"，转化图解决"为什么买"。

## 1. 点击图结构

核心任务：在用户快速滑动时，给用户一个明确点击理由。

需要判断的内容：

| 判断项 | 说明 |
| --- | --- |
| 用户场景 | 用户是在搜索、推荐流、货架页，还是品牌目标购买？ |
| 用户兴趣 | 用户可能被什么吸引？价格、颜值、功能、痛点、场景、稀缺感？ |
| 点击理由 | 这张图和竞品相比，凭什么让用户点进来？ |
| 产品识别 | 用户能不能一眼看懂你卖什么？ |
| 视觉吸引 | 画面有没有足够的识别度和对比？ |

内容组成：点击图 = 图片（产品识别、质感、场景代入）+ 文案（表达点击理由）+ 元素（强化卖点、引导视线、增加信息层级）。

设计公式：点击图 = 产品主体 + 一个核心钩子 + 一个差异点 + 适度信任。
示例（袜子）：产品主体=模特上脚图；核心钩子=不掉跟/显腿细/透气不闷；差异点=镂空暗纹/新疆棉/硅胶防滑；信任点=高弹亲肤/多色可选/日常百搭。

版式原则：

| 原则 | 说明 |
| --- | --- |
| 主体要大 | 产品不能太小，必须一眼识别 |
| 文案要少 | 不要把详情页内容塞进点击图 |
| 层级要清楚 | 主标题最大，副标题次之，标签最弱 |
| 对比要明显 | 大小、粗细、明暗、色彩、疏密形成视觉节奏 |
| 画面要饱满 | 不能空，也不能乱 |
| 留白要克制 | 留白是为了突出主体，不是为了显得空 |

## 2. 转化图结构

核心任务：让已经点进来的用户相信产品值得买。

需要判断的内容：用户需求（真正想解决什么问题）、用户痛点（买同类产品踩过什么坑）、用户顾虑（为什么犹豫不下单）、产品卖点（用什么设计解决问题）、卖点证据（怎么证明）、隐性需求（没直说但在意什么）、差异化（与竞品有何不同）。

## 3. 需求层级（转化图思考框架）

功能需求 → 安全需求 → 便捷需求 → 舒适需求 → 审美需求 → 情绪/身份需求

| 层级 | 用户关心什么 | 示例 |
| --- | --- | --- |
| 功能需求 | 能不能用？ | 防晒、保暖、防滑、收纳、充电 |
| 安全需求 | 靠不靠谱？ | 材质安全、检测认证、不会掉色 |
| 便捷需求 | 方不方便？ | 好穿、好洗、好收纳、好安装 |
| 舒适需求 | 用起来舒服吗？ | 不勒脚、不闷热、不磨脚、不沉重 |
| 审美需求 | 好不好看？ | 显瘦、百搭、高级、颜色好看 |
| 情绪需求 | 符不符合我想要的状态？ | 精致感、松弛感、少女感、专业感 |

## 4. 转化图设计公式

转化图 = 痛点 + 解决方案 + 卖点证明 + 场景展示 + 信任背书
（更简化：用户问题 → 产品卖点 → 证据证明 → 使用场景 → 下单理由）

## 5. 转化图内容顺序

| 顺序 | 图的任务 | 内容重点 |
| --- | --- | --- |
| 第 1 张 | 讲痛点 | 用户为什么需要这个产品 |
| 第 2 张 | 讲核心卖点 | 产品怎么解决问题 |
| 第 3 张 | 讲证据 | 材质、结构、参数、对比 |
| 第 4 张 | 讲体验 | 舒适度、使用感、细节 |
| 第 5 张 | 讲场景 | 日常、通勤、居家、外出、送礼 |
| 第 6 张 | 讲信任 | 品牌、售后、检测、评价 |
| 第 7 张 | 讲购买理由 | 套装、价格、季节、现在买的理由 |

## 6. 卖点提炼结构

有效卖点 = 产品优势 + 用户在意 + 竞品不突出。
只是产品有、用户不关心，不算强卖点；竞品都有，不能作为核心差异化。

卖点提炼表：

| 分析项 | 要回答的问题 |
| --- | --- |
| 产品有什么？ | 材质、结构、功能、工艺、颜色、款式 |
| 用户在意什么？ | 舒适、好看、便宜、耐用、安全、方便 |
| 用户怕什么？ | 掉色、起球、掉跟、勒脚、闷热、踩坑 |
| 竞品怎么说？ | 大部分商家在强调什么？ |
| 我们怎么不同？ | 有没有更具体、更真实、更有画面感的表达？ |
| 怎么视觉化？ | 这个卖点能不能用图片、对比、特写表现出来？ |

## 7. 点击图与转化图的区别

| 维度 | 点击图 | 转化图 |
| --- | --- | --- |
| 目标 | 让用户点 | 让用户买 |
| 信息量 | 少 | 多 |
| 文案 | 短、强、直接 | 有逻辑、有证明 |
| 视觉 | 抢注意力 | 建立信任 |
| 卖点 | 只抓一个核心点 | 多卖点分层展开 |
| 重点 | 兴趣 | 需求 |
| 逻辑 | 快速吸引 | 逐步说服 |
| 错误做法 | 信息太多、画面太乱 | 卖点堆砌、没有证据 |

## 8. 主图设计前的分析流程

1. 明确产品 → 2. 明确用户 → 3. 明确场景 → 4. 找到痛点 → 5. 提炼卖点 → 6. 找到差异化 → 7. 设计点击图 → 8. 设计转化图 → 9. 检查视觉层级 → 10. 检查说服逻辑

## 9. 主图分析模板（与 Design Project State 字段对应）

产品名称（product_facts）/ 目标用户（target_user）/ 用户使用场景 / 用户核心需求 / 用户核心痛点（pain_points）/ 用户隐性需求 / 竞品常见表达（competitor_notes）/ 我们的差异化（selling_points）/ 点击图核心目标 / 点击图主文案（copywriting）/ 点击图画面策略（visual_direction）/ 点击图核心卖点 / 转化图 1-6：痛点、卖点、证据、场景、顾虑、下单理由（layout_plan / production_tasks）

## 10. 最简判断标准（评审用）

点击图检查：用户能不能一眼看懂卖什么？有没有一个明确点击理由？画面有没有对比和吸引力？文案是否短而有力？产品是否足够突出？

转化图检查：有没有解决用户需求？有没有讲清楚用户痛点？卖点有没有证据？有没有体现差异化？有没有降低用户下单顾虑？

## 11. 最终简化模型

点击图：场景 + 兴趣 + 钩子 + 对比 + 识别 —— 吸引用户点进来。
转化图：需求 + 痛点 + 卖点 + 证据 + 信任 —— 说服用户买下来。
